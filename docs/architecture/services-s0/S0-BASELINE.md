## Public API and behavior contract — required invariants for S1–S11

**Transport:** route table in `apps/api/src/routes/index.ts`, `auth.routes.ts`, `pharmacy.routes.ts`, `admin.routes.ts`, `order.routes.ts` and controller code is canonical; S0 does **not** rename routes, exported service functions, HTTP codes, error codes, DTOs or request validation. Preserve `routes.use('/pharmacies', pharmacyRoutes)` and alias `routes.use('/pharmacy', pharmacyRoutes)`. Key examples, relative to route mount: `POST /auth/register`, `POST /auth/login`, `POST /auth/refresh`, `GET /auth/current`, `POST /pharmacies/` (draft creation), `GET /pharmacies/me/pharmacies`, `PATCH /pharmacies/me/pharmacies/:pharmacyId/profile`, `POST /pharmacies/me/pharmacies/:pharmacyId/send-for-verification`, pharmacy-scoped document endpoints, and admin/order APIs. `GET /pharmacies/me/summary` permits no pharmacy; pharmacy-specific operations do not. All actual routes are canonical in routes files; examples are not an exhaustive route registry. **Published TypeScript surface:** `public-exports-and-transactions.json` names and their current source locations; aliases/reexports can require extra examination.

**Role boundary:** `USER_ROLES`: `client`, `pharmacy`, `admin`. Platform Owner is an admin-level permission concept, NOT the same as a Pharmacy Owner (`User` with role `pharmacy`). `PharmacyMembershipRole`: `owner` or `manager`, established by `Pharmacy.ownerId` and `Pharmacy.managerUserIds`. Server-side membership is **scoped by explicit pharmacyId** (`_id: pharmacyId, $or: [{ ownerId: userId }, { managerUserIds: userId }]`) and account/pharmacy blocked-state checks. Current Manager grants: `read_profile`, `read_internal_notes`, `manage_internal_notes`; do not silently grant owner-only profile modifications, pharmacy-documents, product/order/client management. Admin roles do not inherit Owner capabilities automatically. Selection may be implicitly resolved only through the existing explicit 0/1/N guard; preserve 403 for foreign pharmacy, 404 for missing ID, 400 for malformed ID and selection-required error for ambiguous N.

**0 / 1 / N pharmacies:** registration of a Pharmacy Owner creates a User + Owner documents, **zero** Pharmacy records; owner summary can return `pharmacy: null`, but pharmacy-specific writes require a selected pharmacy. **One** accessible pharmacy permits the current guarded single-membership resolution; **N** accessible pharmacies require explicit selection, and one owner's pharmacies may have independent statuses/transactions. A legacy Manager with no owned pharmacies cannot create one. Preserve multi-pharmacy ownership, filtering, list, and blocked-owner cascade behaviors. Tests: `owner-registration-stage-14-18-2.contract.test.ts`, `pharmacy-multi-membership.contract.test.ts`, `owned-pharmacy-registry.contract.test.ts`, `pharmacy-owner-lifecycle.mongo.integration.test.ts` and `check-owner-multi-pharmacy-foundation.mjs`.

**Idempotency:** `createPharmacyDraftService` uses `clientRequestId` UUID, normalized payload SHA-256, unique `(ownerId, creationRequestId)` partial index; identical replay returns HTTP **200**, fresh create **201**, reused UUID with different payload returns `PHARMACY_CREATE_REQUEST_CONFLICT` (409), concurrent retry can return `PHARMACY_CREATE_RETRY`. `ownerId` never comes from browser draft input. Manager order creation and checkout have separate fingerprint/concurrency contracts; do not unify their semantics on assumptions. Private notes, comments and mutation `clientRequestId` deduplication remain owner/actor-scoped. Tests: `pharmacy-create.contract.test.ts`, `checkout-concurrency.contract.test.ts`, `manager-order-idempotency.mongo.integration.test.ts`, `manager-order-request-fingerprint.test.ts`, `order-transaction-boundaries.contract.test.ts`.

**Transactions and audit:** registration persists User, Owner documents, and registration audit in a session. Pharmacy creation persists pharmacy + immutable creation audit **in the same Mongo transaction**. Moderation commits status/review and audit atomically; order checkout/order mutations reserve, release and commit stock in existing session boundaries. Maintain side-effect ordering and rollback/commit behavior. `public-exports-and-transactions.json` is only a location map, not proof of atomicity. Tests include `auth-lifecycle.mongo.integration.test.ts`, `pharmacy-create.mongo.integration.test.ts`, `order-lifecycle.mongo.integration.test.ts`, `order-transaction-boundaries.contract.test.ts`, `checkout-concurrency.contract.test.ts`, `pharmacy-activation*`, `admin-pharmacy-activity.mongo.integration.test.ts` — choose only actual filenames when running.

**Sensitive boundaries:** Owner registration documents ≠ individual Pharmacy verification documents; download ownership is checked. Admin private comments/notes have distinct privacy, audit, idempotency scopes; do not alter audit text policy as part of relocation. Revision-matched pharmacy PATCH and moderation submission must remain atomic. Tests for multi-tenant clients/orders, document scope, blocked states and permissions are required.
