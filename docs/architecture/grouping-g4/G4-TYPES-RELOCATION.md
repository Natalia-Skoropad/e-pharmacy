# Stage G4 — API Types canonical relocation

Source: latest user archive `e-pharmacy-14-20-7.zip` (post G3). This is a **relocation-only** stage. The supplied patch intentionally ships the tooling; it does not pre-move the type modules.

## Immutable grouping boundary

The G0 `docs/architecture/grouping-g0/relocation-plan.json` records 23 `G4` files. All 23 move to a single canonical target each; no file stays at the flat `apps/api/src/types` root. The names, exported values and types, declaration contents, and behavior are unchanged. Do not add back-compatibility forwarding files.

Canonical domains include `accounts`, `admin/access`, `admin/audit`, `admin/employees`, `admin/pharmacies`, `admin/settings`, `auth`, `cart`, `catalog`, `http`, `infrastructure`, `orders`, `owners`, `pharmacies`, and `shared`. G5 utilities remain untouched.

## Express declaration merging

`apps/api/src/types/express.ts` becomes `apps/api/src/types/infrastructure/express.ts`. It still augments `declare module 'express'` → `interface Request` with the same `authSessionId`, `adminAuthorization`, and user fields. Its two *type-only imports* are updated to `../admin/access/admin-access` and `../accounts/user`. The API `tsconfig.json` includes all of `src`, so TypeScript discovers this module by inclusion without any re-export proxy or change to declarations.

## Safeguards

- Check prior completed G1, G2, and G3 maps before G4; reject partial relocation, collisions, path traversal, missing or unexpected flat types, and obsolete proxies.
- `--dry-run` and `--check` are read-only. A complete import/path rewrite and fingerprint preflight occurs before any `--apply` writes.
- Verify all resolvable relative imports, exact source files, unchanged declaration body, immutable raw/normalized fingerprints and no new TypeScript-extension import suffixes.
- `docs/architecture/grouping-g4/source-fingerprints.json` has 23 pinned source and 23 pinned canonical fingerprints derived from the user's **pre-G4** archive. It is not regenerated by the tool.
- M1 historical source checker maps completed G4 destinations back to G0 identities before evaluating its original, unchanged source hashes. G3 checker allows **one** exact post-G4 seed type import hash recorded in `approved-g3-after-g4.json` after it confirms all 23 G4 moves. The G0/G1/G2/G3/M1 manifests are not edited.
- Three previous grouping tests now accept a *fully completed* G4, but still reject partial state or premature G5 movement.

## Execution

From the monorepo root, after unpacking the changed-files-only ZIP:

```bash
pnpm grouping:relocate --dry-run --stage G4
pnpm test:grouping-g4
pnpm grouping:relocate --apply --stage G4
pnpm grouping:relocate --check --stage G4
pnpm check:grouping-g4
pnpm test:grouping-g4
```

Then retest old architecture stages:

```bash
pnpm check:grouping-g1 && pnpm test:grouping-g1

pnpm check:grouping-g3 && pnpm test:grouping-g3
pnpm check:models-m1 && pnpm test:models-m1

```

Full local Gate **before committing**: five `check:source:*` groups, `check:lint:serial`, `check:type-check:serial`, `check:test:serial`, `check:react:serial`, `check:integration:serial`, `check:build:serial`, and `check:deploy-artifact`.

Do not run database migrations/seeds to check a source move. The next independent stage is G5 Utils.
